# Signal CLI Agent

A YAML-driven automation framework that connects to [`signal-cli`](https://github.com/AsamK/signal-cli) via DBus
and maps trusted Signal messages to controlled actions on your host system.

This project is intentionally **extensible**:

- Add rules without modifying the agent
- Store rules in separate YAML files under `rules.d/`
- Use helper scripts for API integrations (Home Assistant, monitoring, etc.)
- Choose reply formats (`full`, `output`, `bare`)
- Support manual runs or persistent systemd user services

---

## Quick Start (Service Mode – Recommended)

From the repo root:

```sh
make quickstart
```

Then:

```sh

```

## Prerequisites

### Install `signal-cli`

Official repo: https://github.com/AsamK/signal-cli  
Install instructions: https://github.com/AsamK/signal-cli#installation

You must register and verify your Signal number before using the agent.

### Python dependencies

- Python 3.10+
- `pydbus`
- `PyYAML`
- `python3-gi` (GLib bindings)

```sh
pip install pydbus pyyaml
sudo apt install python3-gi
```

## Rules and Configuration

### Root config: `rules.yaml`

`rules.yaml` is generated from `rules.yaml.in` by `configure.py`.

It typically contains:

- `globals:` (defaults / behavior)
- `rules_dir:` (directory of rule files, usually `@REPO@/rules.d`)
- optional `rules:` inline list (supported but not recommended)

### Rule files: `rules.d/*.yaml`

The agent loads **all** `.yaml` / `.yml` files in `rules_dir`.

Each file can be written in any of these formats:

1) `rules:` wrapper:

```yaml
rules:
  - name: disk_usage
    sender: "+15551234567"
    trigger: "disk?"
    match: exact
    command: ["df", "-h"]
```

2) direct list:

```yaml
- name: disk_usage
  sender: "+15551234567"
  trigger: "disk?"
  match: exact
  command: ["df", "-h"]
```

3) single rule object:

```yaml
name: disk_usage
sender: "+15551234567"
trigger: "disk?"
match: exact
command: ["df", "-h"]
```

Recommended practice:
- Check in templates: `rules.d/*.yaml.in`
- Let `configure.py` generate real `rules.d/*.yaml` with local values like `@PHONE@`, `@REPO@`, `@USER@`.

## Service Mode

### Install + start

```sh
make quickstart
```

`make install` runs `configure.py` automatically.

### Manage

```sh
make status
make logs
make restart
make stop
```

### Boot-time user services (“linger”)

User services normally start only when you log in. To start at boot:

```sh
sudo loginctl enable-linger <your-username>
loginctl show-user <your-username> | grep Linger
```

`configure.py` can offer to enable linger for you.

## Manual Mode

Start signal-cli DBus daemon:

```sh
signal-cli -a +15551234567 daemon --dbus
```

Run the agent:

```sh
python3 signal-agent.py ./rules.yaml
```

## Reply Modes

Each rule can set `reply_mode`:

| reply_mode | Behavior |
|-----------:|----------|
| `full`     | `[rule] exit=0` + `$ command` + output (default) |
| `output`   | `[rule]` + output only |
| `bare`     | output only |

Example:

```yaml
reply_mode: output
```

---

## Chunked Output

For large outputs:

```yaml
split_reply: true
chunk_size: 1400
numbered_chunks: true
```

If output splits, the agent prefixes each message:

- `[rule message 1/2]`
- `[rule message 2/2]`

If output fits in one message, no chunk prefixes are added.

## Multiple Allowed Senders

You can specify a single sender:

```yaml
sender: "+15551234567"
```

Or multiple senders:

```yaml
sender:
  - "+15551234567"
  - "+15557654321"
```

## Dry Run

Dry-run suppresses sending replies (but still executes commands).

Enable globally in `globals`:

```yaml
globals:
  dry_run: true
```

Or per-rule:

```yaml
- name: example
  dry_run: true
```

Or via CLI:

```sh
python3 signal-agent.py ./rules.yaml --dry-run
```

---

## Test Mode

Test mode evaluates a single message locally and prints the reply that would be sent.
No DBus. No Signal sends.

```sh
python3 signal-agent.py ./rules.yaml --test --sender "+15551234567" --message "disk?"
```

You can also combine with dry-run:

```sh
python3 signal-agent.py ./rules.yaml --test --sender "+15551234567" --message "disk?" --dry-run
```

## Security Considerations

This agent executes host commands triggered by Signal messages.

Strong recommendations:

- Restrict `sender` to trusted numbers (or lists)
- Prefer strict matching (`exact`) over permissive patterns
- Validate regex args and cap ranges
- Use rate limits (`cooldown_sec`, `max_runs_per_hour`)
- Avoid secrets in the repo; store tokens in protected files (`chmod 600`)
- Prefer helper scripts for API integrations
- Run as a low-privilege user

Do not expose this system to untrusted contacts.
